# Datasets and open-source models

The project has **no real labelled distress-call corpus**. None exists publicly
for Indian waters, and real coast guard recordings are not redistributable. So
the *labelled* data is synthetic (generated by this repo), and open datasets are
used for everything that makes it realistic: real noise, real human speech for
ASR benchmarking, real vessel traffic and real weather.

Check each licence when you download. All of the below are fine for non-commercial
university coursework; several (marked NC) are **not** fine for commercial use.

## 1. Data we create (the core labelled dataset)

| Dataset | Size | Produced by | Used for |
|---|---|---|---|
| Synthetic distress dialogues (EN/HI/TA/ML) | 20,000 dialogues, 3 caller styles | `scripts/generate_dataset.py` | Training/evaluating NER, incident classifier, severity, missing-info detection, contradiction detection |
| Synthetic VHF audio | 100-1,000 calls (~5-10 h) | `scripts/synthesize_audio.py` (MMS-TTS + VHF channel sim + real noise) | ASR evaluation (WER vs SNR), audio-to-incident evaluation, dashboard demo |
| Small real-ish test set (you record) | 30-50 calls | Read scripts aloud on a phone in a noisy room | Measuring the synthetic-to-real gap (most important limitation to report) |

How labels are made: the incident (vessel, MMSI, lat/lon, persons on board,
incident types, severity) is **sampled first**, and the dialogue is rendered from
it, with exact character spans. Train/test leakage is controlled by holding out
vessel names and one phrasing per template slot from training.

## 3. Open audio data

### Real Indian-speech ASR evaluation

Kathbath and IndicVoices provide human-recorded Hindi, Tamil, and Malayalam
speech with transcripts. Both Hugging Face repositories currently require
users to accept access terms and authenticate. Do not put Hugging Face tokens
in source files or commit downloaded recordings. The
`scripts/prepare_kathbath_sample.py` utility streams the official `valid` split
from either corpus and saves up to 200 utterances per language, one per speaker.
The current Kathbath sample includes Hindi, Tamil, Malayalam, and Marathi.
Streaming shuffle is bounded; Hugging Face may still transfer a parquet shard
containing selected examples. IndicVoices is much larger overall, so begin with
the smoke sample and monitor network/disk use.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[speech,real-speech]"
hf auth login
.\.venv\Scripts\python.exe scripts/prepare_kathbath_sample.py --per-language 10
.\.venv\Scripts\python.exe scripts/evaluate_indic_asr.py --limit-per-language 10
.\.venv\Scripts\python.exe scripts/prepare_kathbath_sample.py --dataset indicvoices --per-language 10
.\.venv\Scripts\python.exe scripts/evaluate_indic_asr.py --manifest data/real_speech/indicvoices/manifest.jsonl --limit-per-language 10
```

The first two commands make the Kathbath smoke run; the next two make the
IndicVoices smoke run. Once each works, prepare and evaluate the larger sample
with `--per-language 200` and `--limit-per-language 200`. The evaluator compares
the same human recordings in clean and simulated-VHF conditions with the
existing faster-whisper baseline in all four languages and the Hindi/Tamil/
Malayalam Whisper checkpoints where available. Marathi currently uses the
multilingual baseline only. It writes per-utterance predictions and WER/CER, bootstrap
intervals, paired WER differences, and latency to separate directories under
`reports/indic_asr/`. These are Indian-speech ASR tests, **not** maritime
distress-call tests. Keep their metrics separate from the synthetic maritime
benchmark. Checkpoint training-data disclosures should be reviewed and cited;
neither corpus's held-out `valid` split proves that a checkpoint has no
overlapping training data.

IndicVoices is another useful source of spontaneous speech, but its Hugging
Face card currently requires accepting access conditions and sharing contact
information. Its full-length recordings total hundreds of gigabytes, so it is
not the quickest first dataset for a laptop-scale evaluation.

| Dataset | Licence | What we take | Used for |
|---|---|---|---|
| [ESC-50](https://github.com/karolpiczak/ESC-50) | CC BY-NC 3.0 | engine, sea waves, wind, rain, thunderstorm, helicopter clips (~280) | Real background noise mixed into synthetic calls (`scripts/download_noise.py`) |
| [MUSAN](https://www.openslr.org/17/) | CC BY 4.0 | noise subset (11 GB full download, optional) | Larger, more varied noise set |
| [Google FLEURS](https://huggingface.co/datasets/google/fleurs) (`en_us`, `hi_in`, `ta_in`, `ml_in`) | CC BY 4.0 | ~100 test utterances per language | Baseline Whisper WER on **real human** speech per language, to compare with TTS speech |
| [Mozilla Common Voice](https://datacollective.mozillafoundation.org/) | CC0 | EN/HI/TA/ML clips | Optional: more speakers/accents; Whisper LoRA fine-tuning on Colab |
| [AI4Bharat IndicVoices / Kathbath](https://ai4bharat.iitm.ac.in/) | CC BY 4.0 | Hindi/Tamil/Malayalam read + spontaneous speech | Optional: Indic ASR fine-tuning / evaluation |
| USCG released MAYDAY recordings (hoax-call appeals) | US public domain | A handful of real VHF distress calls | Qualitative real-world test of the ASR + extraction pipeline |

Why not train on real distress audio? There is no public, labelled, multilingual
VHF distress corpus. That is the gap this project fills synthetically, and the
report should say so plainly.

## 4. Open-source models

| Task | Model | Licence | Where it runs |
|---|---|---|---|
| Text-to-speech (all 4 languages) | Meta MMS-TTS `facebook/mms-tts-{eng,hin,tam,mal}` | CC BY-NC 4.0 | Laptop CPU |
| Higher-quality Indic TTS (optional) | AI4Bharat Indic-Parler-TTS | Apache 2.0 | Colab GPU |
| Speech recognition | OpenAI Whisper (small/medium) via faster-whisper | MIT | Laptop CPU (small), Colab for medium/large |
| Indic ASR comparison | AI4Bharat IndicConformer | MIT | Colab |
| Translation to English (operator view) | Meta NLLB-200 distilled 600M | CC BY-NC 4.0 | Laptop CPU |
| Stronger Indic translation (optional) | AI4Bharat IndicTrans2 | MIT | Colab / CPU |
| NER, local | CRF (python-crfsuite) | BSD/MIT | Laptop CPU |
| NER, transformer comparison | XLM-RoBERTa base fine-tuned / GLiNER multi | MIT / Apache 2.0 | Colab |
| LLM JSON extraction comparison | Qwen2.5-3B/7B-Instruct (4-bit) | Apache 2.0 | Colab |

Design choice: entities are extracted from the **original-language** transcript,
not from the translation, because machine translation mangles numbers, MMSIs and
positions. Translation is shown to the operator for context only. A good report
experiment compares "translate then extract" with "extract directly".

## 5. Open geospatial / response data

| Dataset | Licence | Used for |
|---|---|---|
| [Open-Meteo forecast + marine API](https://open-meteo.com/) | CC BY 4.0, free non-commercial | Live wind, waves and currents at the distress position (drift model input) |

| [Danish Maritime Authority AIS](http://aisdata.ais.dk/) | free | Same, European waters |
| [Global Fishing Watch](https://globalfishingwatch.org/datasets-and-code/) | CC BY-NC 4.0 | Fishing-effort density in the Indian EEZ: where fishing boats (and so incidents) actually are |
| IMO SMCP (Res. A.918(22)) | reference text | Phrase templates for the dialogue generator |

Note: there is no free live AIS feed for Indian waters, so the prototype uses
simulated vessels of opportunity (`mdi/response/engine.py`). Swap in a real AIS
snapshot when available.
